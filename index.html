⚡ Resident Background Daemon & Web Server Setup

The Sentence Refiner features a persistent resident background daemon that lives in RAM. Instead of incurring Python's cold startup penalty (~50ms) on every hotkey press, the daemon handles requests over a local UNIX domain socket (~/.config/refine_tool/daemon.sock) in sub-2 milliseconds!

1. Managing the Resident Daemon with systemd

The daemon runs as a standard Linux systemd --user service with zero root privileges required:

# Check service status (RAM usage ~22MB)
systemctl --user status refine-daemon.service

# Restart the resident daemon
systemctl --user restart refine-daemon.service

# Stop or disable the daemon anytime
systemctl --user stop refine-daemon.service

2. Starting the Daemon Manually

If not using systemd, you can launch the resident daemon directly from the terminal:

python3 main.py --daemon &

3. Serving this Documentation & Web Portal Locally

To launch this documentation portal and connect it to your live local refiner daemon:

python3 main.py --serve 8080

Then open http://localhost:8080 in any web browser.

How Text Capture & Replacement Works

1. Zero-Copy Capture: When text is highlighted with mouse or keyboard, Linux automatically places it in the PRIMARY selection buffer. The refiner reads this immediately without requiring Ctrl+C.
2. In-Place Paste: When you press Enter or y, the tool restores focus to the active window and triggers a native Wayland accessibility keypress (Ctrl+V) via Atspi, replacing the selected text seamlessly.

🏗️ Architecture & Modular Standards

The project adheres to strict modular separation and uses 100% Python Standard Library. Zero third-party pip dependencies.

daemon/

Persistent UNIX domain socket server keeping models, regexes, and UI hot in RAM for sub-5ms latency.

refiner/

NLP engine with precompiled regexes, LRU cache, Teach mode, dynamic snippets, and cloud AI connectors.

clipboard/

Multi-backend clipboard manager supporting Wayland, X11, and Linux PRIMARY selection buffers.

injector/

Wayland Atspi accessibility keyboard generator, desktop notifications, and audio chime feedback.

ui/

Tkinter dark-mode popup, SequenceMatcher word diff tokenizer, and tabbed settings GUI.

metrics/

Linguistic readability analysis (Flesch Reading Ease score, Grade Level, syllable counter).

config/ & history/

JSON persistence for technical term whitelist, custom snippets, API keys, and audit log.

web_server/

Stdlib HTTP server serving static assets and connecting live browser requests to the daemon socket.

🤖 Hybrid Intelligence: Offline Rules + Cloud AI

By default, the tool runs 100% offline using its precompiled rule engine. Optionally, you can configure cloud AI API keys or local LLM servers. All cloud connectors are written with native urllib.request (zero pip packages required).

❓ Frequently Asked Questions (FAQ)

Q: Does this work inside Antigravity, Google Chrome, Claude web, ChatGPT, and Slack?

Yes, 100%! It works anywhere you can type or highlight text on Linux. Because it uses native OS selection buffers and Atspi accessibility events, it is completely agnostic to the application framework (Electron, Chromium, Gecko, GTK, Qt, or terminal).

Q: Do I need to press Ctrl+C before the shortcut?

No! Just select the text (using mouse drag or Shift+Arrows) and press Ctrl+Alt+R. The tool captures it automatically from the Linux PRIMARY selection buffer.

Q: What is Teach Mode ("Why Changed?")?

Teach Mode provides actionable linguistic reasoning behind every correction. It explains subject-verb agreement, irregular verb forms, typo resolutions, and conciseness improvements.

Q: Can this run completely offline without an internet connection?

Yes! The default built-in rule engine operates 100% locally with zero external network calls.
